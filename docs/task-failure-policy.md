# 任务失败间隔与循环退出

GUI 的“执行任务失败后设定”控制一次任务失败后的下次执行时间。它不负责终止还没返回的任务内部循环。本轮修复同时处理这两个层次。

## 调度行为

- 真实失败从失败结束时刻加上该任务的 `scheduler.failure_interval`，不再被服务器刷新时间、旧任务开始时间或固定 10 秒重试覆盖。
- 未完成任务检查点保存 `not_before`。配置重载、后台重新启动、其他任务调用不能把它提前。沿用未完成任务优先规则；检查点只在本任务完成或被用户禁用时释放。
- 内部 `GotoMain` 使用 `Restart` 的失败间隔；环境恢复另存 `recovery_not_before`，不覆盖业务检查点。空闲失败等待到业务任务和恢复任务较早的到期时间，配置重载仍能中断等待。
- 三次连续真实失败仍使用原来的人工接管/停机策略，但每次之间先遵守配置间隔。`HandleError` 关闭时保留停机策略。
- 活动未开放、挑战冷却、触发其他任务等正常延期用明确的目标时间，并不计为失败。金币、经验、年兽、石距冷却规则不提前。

## 流程上限

- 导航默认累计 64 步、180 秒，最多 2 次 ESC 恢复和 256 次内部轮询；页面变化与恢复不重置总预算。设备性能配置只放大一次默认时间，显式设置的绝对时限保持原意。
- 通用等待、领奖、战斗退出和邀请拒绝有有限预算。点击后用新截图验证目标状态；输入失败或目标始终不出现时抛出 `TaskRecoveryFailed`，交给调度器等待。
- 所有通过 `Device.screenshot()` 的任务调用栈使用 `TaskFlowGuard`。普通点击、动画、清空检测记录不能续期；已验证页面进展可续期 420 秒的无进展预算。已配置的更长战斗、寮监控、LBS 等待和百鬼棋局匹配加载窗口保留。
- 同一活动调用栈还有默认 1800 秒的独立总预算，防止反复切换页面一直续期。只有战斗计数推进或两张新图确认百鬼棋局回合超过已确认最高回合才续期；配置的更长运行窗口会放宽总预算。没有单独时长的长批量整理最多运行到此上限，失败后按间隔继续。
- 百鬼夜行快速截图保留原来独立 180 秒看门狗；地图/账号两处没有新截图的循环已改用有限的单次点击验证。道馆列表按增加的搜索范围终止；大神 Frida 读线程由调用方有限 `join` 控制，不作为游戏控制循环。
- 设备层补充 HTTP minitouch 服务状态/握手、scrcpy 线程启动/新帧等待和 ADB 持续接收的总时限，仍使用原有异常及有限重试。识图缩放改为最多 2048 个样本的有限网格，异常步长不能让计算停止推进。GUI 端口分配遍历有限候选池，全部占用时返回错误。
- 每日琐事失败仍保存前面已经完成的日期，失败的项目继续保留。奉纳选中后 OCR 不稳定或按钮消失直接失败，不再反复重选。寮监控日期只包含今天时下次为七天后，无效日期配置按失败延期。

## 验证与范围

全库静态盘点覆盖 59 个任务入口和安装基线的 484 个任务 `while` 循环；工具同时输出共享模块和调度器循环。表中的“候选”只表示静态语法未发现明确时限，并不代表已证实死循环，需要核对调用方、有限集合、计数器与公共保护。

离线回归使用模拟时钟、模拟截图和真实任务协调逻辑：覆盖配置 3 小时后重试、重载/重启保留时限、ESC/页面切换不能重置预算、旧截图路径、每日进度保存、正常长战斗和百鬼棋局长对局、LBS 等待和无效监控日期。744 项离线测试通过。未再次实机领取已人工购买的每日礼包。

盘点命令（使用本机已安装 Python）：

```powershell
python -B dev_tools/audit_task_loops.py . task-loop-inventory.json
```

保护基于截图的协作检查；阻塞 I/O 仍依赖其已有网络/设备超时，纯数据遍历依据有限输入退出。调试模式显式禁用卡死检测时沿用禁用行为。没有新增第二个游戏控制进程。

## 百鬼棋局指定回退

用户要求只将百鬼棋局恢复到 `35eac6985cf73fe6fad17383d2f75c4810ad2813`（图像帧过期重试、对局内取消点击休息、升级确认后才推进）版本。`tasks/Chess` 中与当前安装不同的三个文件恢复到该提交内容；共享导航中只恢复棋局专用安全结算区域和棋局任务分类，庭院、寮突破等后续修复保留。

购买经验仍只有金币实际下降才确认完成。新循环保护观察旧协调器已有的、经连续新帧确认后返回的回合号，无需改写指定版本的棋局源码。没有恢复已取消的定时跟进，也没有改动本机任务配置或清空未完成检查点。
